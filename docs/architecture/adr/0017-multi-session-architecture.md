# 0017. 支持多会话并发（多标签页架构）

- **状态**：已接受
- **日期**：2026-10-28
- **决策者**：项目所有者

## 背景

在目前的 `IndComm` 架构中，`MainFrame` 使用了一个 `wxSimplebook` 来切换「欢迎页」和「唯一的会话页」。同时，`SessionManager` 被设计为只维护一个活动的 `ISessionPtr`（通过 `SetActive` 替换旧的会话）。

随着现场测试场景的深入，用户提出需要**同时打开多个连接**的需求。例如：
1. 同时连接一个 TCP Server（模拟上位机）和一个 TCP Client（模拟下位机），进行双向透传测试。
2. 同时打开一个 Modbus TCP 连接和多个串口连接，监控不同的设备。
3. 在同一个进程中并行执行多个不同的自动化测试脚本。

当前的「单会话」架构严重阻碍了这些场景的实施。每次切换连接时都必须关闭旧连接，不仅操作繁琐，还会丢失旧连接的运行状态、日志和实时曲线。

## 决策

**将主界面的单会话模式升级为多标签页（Multi-Tab）架构，支持同时打开并管理多个独立连接。**

具体决策如下：
1. **UI 层重构**：将 `MainFrame` 中心的 `wxSimplebook` 替换为 `wxNotebook`（或者更美观的 `wxAuiNotebook`）。
   - 「欢迎页」不再作为独立页面，而是当没有任何连接时，在 Notebook 区域显示的一个默认面板。
   - 每次新建或打开一个连接，就在 Notebook 中新增一个 `Tab`，该 `Tab` 内嵌一个独立的 `SessionPanel`。
2. **会话与状态解耦**：移除 `MainFrame` 中的单例 `SessionManager`。改为在 `MainFrame` 中维护一个 `TabContext` 列表（每个 Tab 记录其对应的 `SessionPanel`、`ISessionPtr`、`ActiveProfile`、文件路径等）。
3. **上下文隔离**：每个 Tab 拥有独立的 `SessionConfig`、变量池、实时图表、日志和测试执行引擎（`TestRunner`）。
4. **菜单和工具栏联动**：全局菜单（如“保存”、“关闭连接”、“配置连接”）的作用对象，从原来的“全局唯一会话”更改为“当前激活的 Tab”。当切换 Tab 时，主窗口标题、状态栏和菜单的启用状态随之更新。
5. **资源与依赖共享**：底层的 `Database`（SQLite）和 `TestRunner` 线程依然相互独立；但如果需要，可以共享同一个 SQLite 数据库实例进行并发写入（通过 WAL 模式保证）。

## 替代方案

| 方案 | 为什么没选 |
|---|---|
| 采用多窗口（Multiple Windows）模式 | 用户需要频繁在不同窗口间切换，且任务栏会显得非常臃肿。工业现场更习惯在一个主窗口内通过标签页管理任务。 |
| 一个 Tab 内用分屏展示两个连接 | 限制了并发数量，如果用户想同时开 3 个、4 个连接，分屏逻辑会极其复杂且屏幕空间不够。 |

## 后果

**好处**
- **体验飞跃**：测试工程师可以在一个软件实例中同时监控多个设备，无需来回点击。
- **上下文完整**：每个连接的收发日志、曲线图表、变量状态完全保留。
- **架构标准化**：后续支持“联动测试”（如 A 收到数据后触发 B 发送）在底层成为可能。

**代价 / 限制**
- `MainFrame` 的逻辑会变复杂，需要仔细管理 `Tab` 的生命周期。
- 需要处理并发资源竞争，比如同一个 `.json` 文件被多个 Tab 同时打开时的修改标记冲突。
- 在关闭主窗口时，需要遍历所有 Tab 逐个询问“是否保存”。

**后续必须遵守的约束**
- 严禁在 `MainFrame` 中继续保留单一 `m_sessionMgr` 的全局变量。
- 每个 Tab 的 `SessionPanel` 必须独立管理自己的 `ISession` 生命周期。
- UI 的任何“全局”状态更新（如标题栏），必须基于 `GetCurrentTab()` 触发。
