# 0013. 引入统一应用设置对话框与偏好持久化

- **状态**：已接受
- **日期**：2026-10-23
- **决策者**：项目所有者

## 背景

`IndComm` 经过阶段 1~12 的发展，功能已涵盖多协议（TCP、串口、Modbus、MQTT）、自动化测试、数据持久化等核心能力。但应用级偏好（如 HEX 显示、自动滚动、时间戳、字体、关闭行为等）存在以下问题：
1. **配置割裂**：`SessionPanel` 中的 HEX 显示、自动滚动等开关仅存在于当前会话的内存中，关闭程序即丢失，且不同会话之间不共享。
2. **缺乏统一入口**：用户如需修改界面行为，必须在各个零散的菜单项或面板中寻找，交互体验极差。
3. **硬编码行为**：关闭窗口时的“最小化到托盘”提示是写死的，无法根据用户习惯进行配置。
4. **预留模块未落地**：`settings/` 模块中的 `FontSettings` 和 `ThemeSettings` 虽已预留接口，但缺乏实际的 UI 调用入口。

## 决策

**引入统一的 `ui/SettingsDialog`，并将全局 UI 偏好纳入 `UISettings` 进行集中持久化。**

具体决策如下：
1. **建立统一设置对话框**：新增 `ui/SettingsDialog`。通过菜单栏 `设置 -> 选项...` 唤起。
2. **分类管理**：对话框内使用 `wxNotebook` 划分为“通用”、“界面与日志”、“编辑器”等选项卡。
3. **全局偏好收敛**：
   - 将 `SessionPanel` 中的“HEX 显示”、“时间戳”、“自动滚动”等状态提取到 `UISettings`。
   - `SessionPanel` 在构建时从 `UISettings` 读取默认状态，并绑定相关事件。
4. **修改即生效**：对话框提供“应用”按钮，点击后立即通过事件机制通知 `MainFrame` 和所有活动的 `SessionPanel` 刷新 UI 状态，无需重启。
5. **主窗口行为配置**：将“关闭时最小化到托盘”的偏好固化到 `UISettings`，`MainFrame` 在 `OnClose` 中读取该配置。
6. **字体/主题预留**：`SettingsDialog` 中提供字体和主题的选择 UI，并驱动 `FontSettings` 和 `ThemeSettings` 进行应用。

## 替代方案

| 方案 | 为什么没选 |
|---|---|
| **继续在菜单栏堆叠开关** | 随着设置项增加，菜单会变得极其臃肿，且不符合现代桌面软件的操作习惯。 |
| **在各组件内提供局部设置** | 配置割裂，数据源不统一，用户难以获得全局一致的使用体验。 |
| **修改配置后必须重启应用** | 极大地降低了调试效率，特别是工业现场需要频繁调整日志显示格式的场景。 |

## 后果

**好处**
- **体验统一**：所有应用级偏好集中在同一个对话框，操作路径极短。
- **状态共享**：HEX 显示、自动滚动等开关在多会话间全局生效，提升了调试体验。
- **架构对齐**：完全符合「单一数据源」原则（`Settings` 是唯一底层存储消费者）。
- **即改即生效**：通过自定义事件广播，UI 状态可以在不重启的情况下实时更新。

**代价 / 限制**
- **状态同步复杂**：需要引入全局事件（如 `wxEVT_SETTINGS_CHANGED`）来通知所有打开的窗口和面板。
- **代码量增加**：新增了 `SettingsDialog` 的几百行 UI 代码，且 `SessionPanel` 的状态管理逻辑需要重构以适配外部设置。

**后续必须遵守的约束**
- 严禁在 `SessionPanel` 或 `MainFrame` 中直接读写本地文件或 `wxConfigBase`。必须通过 `settings::UISettings::Instance()` 进行读写。
- 新增全局 UI 偏好时，必须同时在 `SettingsDialog` 中添加对应的控件，并在“应用”操作中调用 `Flush()`。
