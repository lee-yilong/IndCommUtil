# 0018. 列表操作快捷键与键盘 UX 优化

- **状态**：已接受
- **日期**：2026-10-29
- **决策者**：项目所有者

## 背景

在 `IndComm` 当前的 `SessionPanel` 中，用户对「通信变量」和「测试步骤」的所有增删改查操作都严重依赖鼠标点击（如点击“添加”、“复制”、“编辑”、“删除”按钮）。

对于工业现场频繁进行调试和编辑的工程师来说，鼠标操作效率低下。用户迫切希望拥有类似 Windows 资源管理器的原生键盘体验：
1. `Ctrl+N`：新建（变量或步骤）。
2. `Ctrl+C`：复制选中项。
3. `Ctrl+V`：粘贴（目前上下文理解为复制并插入）。
4. `Del`：删除选中项。
5. `Ctrl+E`：编辑选中项。
6. `↑` / `↓`：上下切换选中项。

## 决策

**在 `SessionPanel` 的「通信变量」和「测试步骤」两个 `wxListCtrl` 控件上，统一绑定键盘快捷键事件。**

具体策略如下：
1. **事件绑定**：为两个列表控件绑定 `wxEVT_KEY_DOWN` 事件。
2. **按键映射**：
   - 检测 `evt.ControlDown()` 与键值 `N`、`C`、`V`、`E`。
   - 检测 `WXK_DELETE` 键。
   - 检测 `WXK_UP` 和 `WXK_DOWN`。
3. **逻辑复用**：为了避免代码重复，快捷键触发时，不在事件内重写业务逻辑，而是通过 `wxPostEvent` 向对应的 UI 按钮（如 `m_addVarBtn`、`addBtn` 等）发送 `wxCommandEvent(wxEVT_BUTTON)`，从而原封不动地复用现有的按钮点击逻辑。
4. **焦点处理**：`wxListCtrl` 自带上下键的选中支持，但为了确保操作连贯，当焦点在列表上时，按 `Ctrl+N`、`Ctrl+C` 等会直接触发右侧对应的按钮动作。
5. **粘贴实现**：在当前阶段，由于没有复杂的跨实例剪贴板，`Ctrl+V` 的行为等同于 `Ctrl+C`（在选中项下方插入一个副本）。

## 替代方案

| 方案 | 为什么没选 |
|---|---|
| 仅在主窗口菜单中注册快捷键 | 菜单快捷键是全局生效的，但在多个标签页存在时，无法精准识别当前焦点是在哪个标签页的哪个列表上，容易导致错误的操作对象。 |
| 使用 `wxAcceleratorTable` | 同样面临焦点传递的问题，且无法单独为变量列表和步骤列表配置不同的上下文快捷键（如新建变量和新建步骤的差异化）。 |
| 重写 `wxListCtrl` 子类 | 会增加大量不必要的代码复杂度，修改现有的 `SessionPanel` 是最轻量、侵入性最小的做法。 |

## 后果

**好处**
- **效率大幅提升**：符合用户日常使用 Windows 软件的直觉，减少鼠标移动。
- **零业务逻辑重复**：通过模拟按钮事件，避免了在快捷键响应中重写增删改查逻辑。
- **精确的作用域**：快捷键严格绑定在对应的列表控件上，互不干扰。

**代价 / 限制**
- 必须保证按钮对象在快捷键触发时是存活的（在 `SessionPanel` 生命周期内成立）。
- 当焦点在列表内的其他可编辑控件时，`Ctrl+C` 等可能会被系统原生复制覆盖（需要判断当前焦点是否在 `wxTextCtrl` 内）。

**后续必须遵守的约束**
- 快捷键的监听必须放在具体的列表控件上（`m_varList` 和 `stepList`），不得滥用全局热键。
- 若新增列表操作，必须同时提供对应的按钮 UI 和快捷键绑定。
