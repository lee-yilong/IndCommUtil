# 0011. 会话面板（SessionPanel）UX 交互优化与重构

- **状态**：已接受
- **日期**：2026-10-20
- **决策者**：项目所有者

## 背景

在阶段 8 和阶段 9 中，我们快速实现了通用的自动化测试引擎（`TestRunner`）和独立的 CLI 工具。但是，GUI 层的 `SessionPanel` 仍存在多处历史遗留的交互痛点，导致用户体验割裂、界面拥挤，主要体现在：

1. **变量定义与操作参数割裂**：用户若要修改变量（如重命名、修改类型或权限），必须打开一个包含裸 JSON 的弹窗；而在底部的“操作请求”表单中修改了参数（如寄存器地址），若不点击执行，修改也不会被保存。
2. **测试步骤编辑极度原始**：添加或编辑测试步骤时，依赖原始的 JSON 文本输入。这对工业测试工程师极不友好，容易产生语法错误，且无法直观地选择变量和动作（Action）。
3. **界面空间极其拥挤**：在“手动模式”下，变量列表、参数请求表单、日志区和发送区自上而下堆叠，导致垂直空间被严重挤压，滚动条过长。
4. **测试执行与日志脱节**：在执行交互或自动模式时，界面弹窗只提示“成功/失败”，无法直观地看到该步骤对应的底层通信报文，导致故障排查困难。

## 决策

**对 `SessionPanel` 的 UI 结构与交互逻辑进行深度重构，提升工业场景下的易用性。**

### 1. 彻底废除测试步骤的 JSON 编辑器
- 新增 `TestStepEditDialog` 类。
- 界面上使用下拉框（`wxChoice`）选择 `Action`（Read/Write/Send/Delay），使用下拉框选择引用的 `Variable`，使用输入框填写 `value` 和 `wait_ms`，并使用控件配置 `Assert`（下拉选正则/等值/大于等）。
- 通过对话框的属性直接生成对应的 `nlohmann::json` 结构。

### 2. 变量管理与操作面板的双向绑定
- **变量属性修改**：新建 `VariableEditDialog`，使用表单控件让用户修改变量的名称、类型（int/string等）、权限（RO/RW/WO），以及协议专属参数（基于协议类型动态生成UI）。
- **参数实时同步**：用户在底部的“Variable Operation Request”区域修改参数或 Target Value 时，实时同步写回 `m_sessionConfig->variables`，无需再单独点击保存。

### 3. 引入可拖拽的分栏布局（Splitter）
- 重构 `SessionPanel` 的布局。
- 采用 `wxSplitterWindow`（垂直或水平分栏），将“变量配置/操作区”与“底层通信日志区”彻底分离。让用户可以根据当前的工作重点（配置 or 观察日志）自由拉伸窗口比例。

### 4. 执行可视化（Trace 与 UI 联动）
- 在 `TestRunner` 的步骤执行过程中，UI 列表应自动选中（高亮）当前正在执行的步骤。
- 将执行过程中的底层收发报文（从 `OnRawData` 回调中获取）实时输出到统一的日志视图中。用户点击某一步骤时，可以直观地看到该步骤对应的报文。

## 替代方案

| 方案 | 为什么没选 |
|---|---|
| 保持 JSON 弹窗编辑 | 违背了“零代码 UI 数据驱动”的设计初衷，用户学习成本极高。 |
| 继续使用平铺布局 | 在调整窗口大小时体验极差，无法适应不同分辨率的工业现场屏幕。 |
| 新增一个独立窗口来展示变量 | 切换窗口会导致焦点丢失，打断连续调试的思路，不如分栏直观。 |

## 后果

**好处**
- 测试工程师不需要再写任何 JSON 代码，完全通过 GUI 控件即可完成所有操作。
- 界面结构更清晰，多窗口分栏让调试过程更透明。
- 彻底解决配置丢失、状态不同步的问题。

**代价 / 限制**
- 需要新建两个 `wxDialog` 类（`TestStepEditDialog` 和 `VariableEditDialog`），UI 代码量会增加。
- `SessionPanel` 的布局代码和 `TestRunner` 的回调绑定需要大幅重写。
- 不再兼容旧版本面板直接修改 JSON 的方式（底层数据格式依然兼容）。
